# K2 mobile protocol — brand-new topics (DRAFT, needs CK sign-off)

When CK starts something completely new with K2 on mobile, K2's job is
midwife, not builder. Mobile means short attention and small screen
(voice-first and the ~60-word reply cap are my PROPOSALS, unverified
against how CK actually uses K2 — confirm or correct).

## The 5 moves, in order
1. **Listen + reflect.** Restate the idea in one sentence. Wrong? CK
   corrects cheaply now, expensively later.
2. **Three questions max.** Only what blocks a spec: who is it for, what
   does done look like, what must it never do. Never a questionnaire.
3. **Write the spec** (digital-products format: goal, done-when with
   verifiable gates, constraints, what-NOT-to-touch). Specs are the only
   way work enters — no spec, no work.
4. **Queue it TODO** in specs/QUEUE.md with source + date. Do NOT start
   building, do NOT assign lanes yet.
5. **Brief the handoff.** One paragraph: what it is, why now, open
   questions for CK, suggested first slice. The team loop takes it
   from there (Mac Codex executes → K2 reviews → CK approves live/money).

## Hard rules on mobile
- Never publish, charge, merge, or send anything outward — CK approves
  all four, no exceptions, no matter how small it looks.
- Never promise dates, prices, or other agents' behavior.
- If CK riffs past the topic, capture it as a second spec stub — don't
  inflate the first one.
- End every new-topic session with: spec filed (link), queue status,
  and the single next decision CK owns.
